Task 1
Project Architecture and Data Models
Learn how to build the foundation of a real backend project. You will set up the MVC folder structure, configure environment variables, design Mongoose schemas for five different models, and create a seed script to fill your database with sample data — before writing a single route.

In this task, you will build the complete foundation of the backend project — the folder structure, the data models (called Schemas), and the database connection. This is the most important part of the project, because every other task you build later depends on it.

💡
What is Project Architecture?
Project architecture is the way you organize your code into folders and files before you start writing features. A well-organized backend project follows the
MVC pattern
(Model – View – Controller), which keeps your database logic, your business logic, and your routes completely separated. This makes the project easier to read, easier to debug, and easier for a whole team to work on together.

4. What Is a Mongoose Schema?
A Schema defines the shape of a document inside a MongoDB collection — which fields it has, what type each field is, and any rules the field must follow (like required or unique). Mongoose turns a Schema into a Model, which is the object you actually use to create, read, update, and delete documents.

5. User Schema
models/user.model.js
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema({
  name:     { type: String, required: true, trim: true },
  email:    { type: String, required: true, unique: true, lowercase: true, trim: true },
  password: { type: String, required: true, select: false },
  role:     { type: String, enum: ['attendee', 'admin'], default: 'attendee' }
}, { timestamps: true });

module.exports = mongoose.model('User', userSchema);

7. Event Schema
The Event Schema uses two references (ObjectId with ref) — one pointing to the Category it belongs to, and one pointing to the User who organized it.

models/event.model.js
const mongoose = require('mongoose');

const eventSchema = new mongoose.Schema({
  title:       { type: String, required: true, trim: true },
  description: { type: String, required: true, trim: true },
  category:    { type: mongoose.Schema.Types.ObjectId, ref: 'Category', required: true },
  date:        { type: Date, required: true },
  city:        { type: String, required: true, trim: true },
  venue:       { type: String, required: true, trim: true },
  capacity:    { type: Number, required: true, min: 1 },
  organizer:   { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true }
}, { timestamps: true });

module.exports = mongoose.model('Event', eventSchema);

📘
What does ref do?
ref tells Mongoose which collection an ObjectId belongs to. This allows you to use .populate() later to automatically fetch the full related document instead of just its id. Population will be explained in detail in a future advanced lesson.

8. Registration Schema
A Registration links one attendee to one event. To prevent the same user from registering for the same event twice, we add a unique compound index on the pair of fields.

models/registration.model.js
const mongoose = require('mongoose');

const registrationSchema = new mongoose.Schema({
  event:    { type: mongoose.Schema.Types.ObjectId, ref: 'Event', required: true },
  attendee: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true }
}, { timestamps: true });

registrationSchema.index({ event: 1, attendee: 1 }, { unique: true });

module.exports = mongoose.model('Registration', registrationSchema);

10. The Seed Script
A seed script is a small program that fills your database with sample data automatically, so you do not have to add it by hand through Postman every time you reset the database.

💡
Delete in the correct order
Before inserting new data, the script must clear old data first — and it must do so in an order that respects the references, so you never delete a document that another document still points to.

Term	Definition
MVC	Model – View – Controller. A pattern that separates data (models), request logic (controllers), and routing so each part has one clear job.
Schema	A blueprint that defines the fields, types, and rules of a document stored in a MongoDB collection.
Model	The object created from a Schema that you use to actually interact with a MongoDB collection (create, read, update, delete).
ObjectId	MongoDB's unique identifier type, used to reference a document in another collection.
ref	A Schema option that tells Mongoose which model an ObjectId field is pointing to.
unique index	A rule on the database that prevents two documents from having the same value (or combination of values) in a field.
.env file	A file that stores configuration values and secrets outside of your source code, loaded using the dotenv package.
middleware	A function that runs between the incoming request and the final controller, often used for validation, authentication, or logging.
JWT	JSON Web Token — a signed token used to verify a logged-in user without storing session data on the server.
bcrypt	A library used to hash passwords so the real password is never stored in the database.
seed script	A script that automatically fills the database with sample data for testing and development.
timestamps	A Mongoose Schema option that automatically adds createdAt and updatedAt fields to every document.
